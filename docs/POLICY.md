# Policy and risk review

This is a design review of a personal tool, not legal advice.

## Data and privacy

- **No telemetry.** The manifest declares that the extension collects no data. Nothing is sent to the author or any analytics service.
- **Where data goes.** Only to servers the user configures: their Miniflux, their Fastmail WebDAV and Raindrop (api.raindrop.io). Article text stays in Miniflux and the local cache.
- **Browsing history.** History and bookmarks are read locally to build the echo profile. Only a term vector and domain counts leave the machine, and only to the user's own WebDAV folder. Page URLs and titles of visited pages are not uploaded.
- **Credentials.** The Miniflux key, WebDAV app password and Raindrop token are stored in the extension's local storage, which Firefox keeps unencrypted in the profile folder. Anyone with access to the profile can read them. Use a Fastmail app password limited to Files, and a Miniflux key you can revoke. From 0.4.0 the keys, settings, folder order and look are carried through Firefox Sync by default (two switches on Move setup turn it off), because a second machine otherwise starts empty. Firefox encrypts extension storage in Sync end to end with the Firefox account, but anyone who controls that account, or any machine signed in to it, can read the keys. A machine with no keys never writes to Firefox Sync, so a fresh install cannot overwrite a good setup. Whether Add-ons data is included depends on the user's Firefox Sync choices on both machines.
- **Settings file.** The exported file holds keys only if the user chooses a passphrase; they are sealed with PBKDF2-SHA256 (250,000 rounds) and AES-256-GCM. A weak passphrase weakens the seal. Without a passphrase the keys are left out. The file may include the reading history if ticked; it then holds exactly what the event log holds and nothing more. Importing never changes the machine's name.
- **Copied setup text.** The same sealed format as the file, without history, placed on the clipboard at the user's request. It sits in the clipboard and wherever the user pastes it, so the passphrase is the only protection.
- **Machine-name safeguard.** Each install has a random id. If two installs use one machine name, the second is stopped before it writes, because two writers on one log could mix history.
- **Outside scoring.** `enrich/outbox.json` holds titles, summaries and links of borderline articles and the top terms of the interest profile. If the user connects an outside assistant, those leave the user's storage. Turning this on is the user's decision, and the file contains no credentials.

- **Thumbnails and images.** When thumbnails or article images are shown, the browser loads them from the publisher's site, which reveals the user's IP address to that site. Thumbnails can be turned off in Settings. Feed icons come from Miniflux, not from publishers.

- **Fonts.** From 0.7.0 Pravaha carries only two typefaces, both Apple's: SF Pro (sans) and New York (serif). Their licence limits use and redistribution, so the repository never contains them: `tools/apple-fonts.py` builds them on the owner's machine into a git-ignored folder, and an extension built that way is for the owner's own use and must not be published or shared. The signed build goes to Mozilla's unlisted channel, which does not publish it, but the owner should still treat that file as private. The open fonts bundled before 0.7.0 (OFL families and Ubuntu) were removed to keep the extension small, together with their licence files; a build made without the Apple files falls back to the system serif and sans, and the picker says the Apple faces are not in that build. No font is fetched from the web at read time.
- **Bundled code.** `extension/vendor/bionify.mjs` carries the word rules of Bionify (GPL-3.0, licence file alongside), with the delivery changed so it builds DOM nodes instead of assigning HTML. It runs locally on text nodes of already sanitised content and makes no network calls. Because it includes GPL-3.0 code, Pravaha as a whole is distributed under GPL-3.0: anyone who receives the add-on is entitled to the source, which the source zip provides. The name "Bionic Reading" is a registered mark of its owner, so the interface calls the setting "Anchor bolding".

- **Feed discovery and subscribing.** The Add feed dialog sends the address the user typed to the user's own Miniflux (`POST /discover`), and Miniflux's server then fetches that page. The extension does not contact the site itself, so the site sees Miniflux's address and not the reader's. The right-click item "Subscribe with Pravaha" passes only the address of the page or link that was clicked, and only after the click. By default the extension has no content script and does not read pages; the optional feed detection below is the only exception. Subscribing and creating a folder are written to Miniflux only when the user presses the button. Feed addresses from the discovery reply are accepted only if they begin with `http://` or `https://`.
- **Search index.** The search index holds titles, feed names, tags, short summaries and a few keywords for articles read in the last 400 days, on this machine only. It is not uploaded. It extends how long the reader remembers what was read: an article read months ago stays findable after its text is gone from the reading cache. It can be cleared by removing the extension's data. It stores nothing that Miniflux does not already hold.
- **Older-article search.** The "Search Miniflux for older" button sends the user's search words to the user's own Miniflux. Operators such as `#tag` and `in:read` are removed before sending.

## Third-party terms

- **Miniflux.** Uses the documented REST API with a personal API key. Polling is every two minutes by default against the user's own account, which is within normal use for a hosted account. Raise the interval if the host asks.
- **Raindrop.** Uses the official REST API with a personal test token. Reading is paged and cached for a day. Saving is one way. The claim that Raindrop generates tags with a local model is unconfirmed, so Pravaha does its own local tag matching instead.
- **Fastmail.** Uses WebDAV with an app password, as Fastmail documents for Files.
- **Mozilla.** Distributed as a self-signed (unlisted) add-on, which Mozilla's terms allow. It is not listed on addons.mozilla.org, so it does not go through listed-add-on review.
- **Publishers.** Pravaha shows Miniflux's own content and links out to the original page. It does not bypass paywalls and does not scrape. The full-article button asks Miniflux to fetch the page, using Miniflux's own content fetcher from the user's own server, only when the user presses it. Pravaha never requests the publisher's page itself.

## Behavioural risks of the 0.3.0 actions

- **Bulk mark-read is the one action that can hide a lot at once.** It asks for confirmation by default for a section, a folder and "mark all", and says how many articles it will touch. The result message offers Undo, which puts exactly those articles back as unread in Miniflux. A single article never asks unless the user turns on "Always ask". Scrolling past an article never asks, because it is automatic and affects only that article.
- **The reader does not claim success it did not get.** After a bulk mark it asks Miniflux which articles are still unread and sends those again, up to three rounds. If some still did not stick, the message says how many and that they will be retried. The 10 minute re-send window can, at worst, mark read again an article that the user marked unread on another machine within that window; it gives up after three tries.
- **Marking by scope reaches articles that are not on screen**, because the section or folder is the unit, not the visible rows. That is the intended fix, and the confirmation states the real count (for example "Mark 312 articles in Naval Wire as read") so it cannot be a surprise.
- **Reordering** changes only the order shown here. It never renames or moves anything in Miniflux.

## Behavioural risks of ranking

- **Filter bubble.** Ranking by similarity to what you already read narrows what you see. The novelty boost, the serendipity flag from outside scoring and the Unread view in feed order are the counterweights. The Ranked toggle is optional, and the default view is grouped by feed.
- **Not a quality signal.** A high score means similar to your habits. It does not mean accurate, current or well sourced. For clinical or policy reading the user remains responsible for appraising the source.
- **Dismiss cost.** Dismissing lowers a feed's standing, which can hide a good feed after a few impatient clicks. Dismissals are reversible with Undo dismissed, and standing fades with a 14 day half life.
- **Explainability.** Every score has a plain sentence saying why, and the details row shows the four components. No hidden signals are used.

## Security review

- UI text is inserted as text nodes. Article HTML is rebuilt by an allowlist sanitiser (`src/safehtml.js`) that parses it into an inert document and copies only known tags and attributes into DOM nodes. Scripts, frames, forms, styles, SVG, event handlers, `javascript:` and `data:` links, and `srcset` are dropped. Links get `noopener`. There is a node limit. `innerHTML` is never used.
- The extension page's content security policy is Firefox's default for extensions, which blocks inline and remote script.
- Article links open in a background tab with a normal browser navigation. Card content is Miniflux's HTML after sanitising.
- Host permissions are limited to the three default services. Other servers need an explicit prompt. The `menus` permission was added in 0.3.0 for the right-click item; it cannot read pages. The right-click item is titled "Subscribe with Pravaha" (0.5.0). The address handed to the reader through the link is URL-decoded, must start with `http://` or `https://`, and is only put in a text box for the user to press Find feeds.
- The WebDAV client builds URLs from path segments with encoding, so a hostile file name cannot escape the folder.
- Corrupted or malicious lines in another machine's log are validated and skipped. They cannot execute and cannot overwrite local state, because merging only adds events with valid shape.
- A malicious other machine with write access to the same WebDAV folder could add events, for example mass dismissals. Treat the folder as trusted.

- **Feed detection (0.5.0, off by default).** The all-sites permission is optional and is asked for only when the person turns on Settings, This machine, "Detect feeds on pages", after Pravaha explains it in its own words (Firefox's own wording cannot be changed). Once granted, a content script is registered dynamically. It reads only `link[rel=alternate]` tags in the top page's head with an RSS, Atom or JSON feed type, and sends their addresses and titles to the background page with `runtime.sendMessage`. It does not read page text, forms, cookies or storage, makes no network request, and sends nothing outside the browser. The background page accepts only messages from its own tabs, keeps at most eight http(s) feeds per tab, drops anything else, holds the result in session storage until the tab navigates or closes, and never writes it to disk or to the history. Turning the switch off unregisters the script and removes the permission, and withdrawing the permission in Firefox does the same. The `scripting` permission was added for this and carries no warning by itself.

- **Feed management and server checks (0.6.0).** Pravaha now writes more to Miniflux, always on an explicit click: rename, move or disable a feed (`PUT /feeds/{id}`), rename a folder (`PUT /categories/{id}`, one call per folder), delete a feed (`DELETE /feeds/{id}`), and ask Miniflux to fetch (`PUT /feeds/{id}/refresh`, `/categories/{id}/refresh`, `/feeds/refresh`). No new browser permission is needed; the host permissions are unchanged. Delete is the only destructive action: it needs the feed's exact name typed, offers Disable instead, and removes the feed's articles in Miniflux, which cannot be undone. A folder rename is several calls; if one fails, the sentence says which were done, and the next refresh re-reads Miniflux so the page never keeps a name Miniflux did not accept. Refresh requests are rate limited by Miniflux, a 429 is explained in plain words, and a folder or all-feed refresh is one request that Miniflux carries out itself, so Pravaha does not hammer publishers.
- **Server contract check (0.6.0).** Every refresh checks that Miniflux's answers have the fields Pravaha relies on, and leaves out any item that does not, so a silent server update cannot write wrong data. The Sync page shows the result as a light, and the toolbar button wears "!" in red or amber. "Check server" is read-only: it reads the version, a page of entry numbers, one entry and the feed list, and it does not start a fetch or change anything. Nothing about the server is sent anywhere except to the Miniflux address the person entered.

## Behavioural risks of training (0.7.0)

- **A thumb is a guess about why you liked something.** It trains the article's top tags and words, not the reason. A thumbs up on a good article about a topic you dislike lifts that topic a little. The weight is deliberately small (0.3 of a click per rule, capped at 0.2 in total) and a second press removes exactly what it set.
- **Training can narrow what you see.** Rules persist until cleared and, unlike feed standing, do not fade. Stats lists every rule with a Remove button, and the digest prints what is currently set to more and less, so the narrowing is visible. A thumbs up also pulls the interest profile (rate 0.08); a thumbs down does not push it away, so the profile cannot be driven negative.
- **Words and tags are personal.** Rules, thumbs and the digest section name your interests. They are stored in the local event log and shared through the WebDAV history log (and so end up in your Fastmail account) like every other event; they are not sent anywhere else. The Raindrop context shown on a card comes from the copy already kept for ranking and is never sent on.
- **A wrong "you saved this".** The exact-match claim rests on the page address after tracking parameters are removed. A site that serves different articles from one address with a changing query is treated as one page only if the parameters are tracking ones, so a false match is unlikely but not impossible. "Close to something you saved" is a text similarity, not a claim of sameness.

## Residual risks to accept knowingly

- Unencrypted keys in the Firefox profile, and, with Firefox Sync carrying them, readable by whoever controls the Firefox account.
- Firefox Sync's cloud delivery was simulated in testing, not observed.
- Two machines may show slightly different scores until their inputs match.
- Real-server behaviour is not yet verified (see README). The 0.6.0 calls (entry numbers, position marker, feed and folder changes, folder refresh) were written from Miniflux's documentation and tested against a fake; the Check server button is the first live test.
